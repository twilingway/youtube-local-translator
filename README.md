## Быстрый запуск

Требуется Windows, Chrome 116+, NVIDIA с актуальным драйвером, `uv`, Node.js и свободное место примерно15–25ГБ (с Qwen3-TTS и кешами больше). FFmpeg в PATH нужен для подгонки темпа озвучки; Faster-Whisper использует PyAV.

Из PowerShell в `E:\MySource\translate`:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File scripts\start.ps1
```

Setup скачивает Python в `.runtime`, создаёт `.venv`, скачивает Whisper, модели голосов, Qwen и проверенный portable CUDA llama.cpp, распаковывает portable Ollama и скачивает TranslateGemma. Silero используется один раз для подготовки коротких стартовых WAV, если их нет; рабочий Qwen-процесс его не загружает. Глобальное Python-окружение и PATH не меняются. Остановить сервис — Ctrl+C в его терминале. Перед готовностью сервер прогревает перевод и синтез.

После загрузки моделей сервис работает без обращения к облачному ASR/переводу/TTS. Сам YouTube требует Интернет. `start.ps1` включает offline-режим Hugging Face и `OLLAMA_NO_CLOUD=1`.

## Расширение и просмотр

1. Chrome → `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное расширение» → папка `E:\MySource\translate\extension`.
2. Откройте `https://www.youtube.com/watch?v=...`, оставьте скорость источника **1×**. «Переводить» попробует запустить источник на паузе; если Chrome запретит воспроизведение, появится просьба нажать Play в YouTube.
3. Нажмите расширение «Локальный перевод YouTube», выберите режим, число участников и стартовый буфер (по умолчанию60сек). «Исходные сегменты в RAM» сохраняет исходные сжатые байты и открывает вкладку нашего плеера. Старое «Исходное YouTube» открывает вторую страницу YouTube и может повторно загружать медиа. «Захват вкладки» кодирует задержанную копию; доступны разрешение720–2160p,30/60FPS и битрейт1–24Мбит/с. Затем «Переводить».
4. В RAM-режиме открывается вкладка нашего плеера, исходная вкладка продолжает играть впереди. Второй штатный YouTube-плеер используется только старым исходным режимом; отдельное окно доступно для видеозахвата. Дождитесь накопления: просмотр начнётся сам. Если появится «Включить звук», нажмите один раз. Повторный запуск возвращает к существующему плееру.
5. Кнопка ▶/❚❚ и Пробел управляют воспроизведением, CC/C — субтитрами, ⛶ — полным экраном. Скорость 0.75–2× меняет задержанное видео и русскую речь с сохранением тембра. Настройки громкости, стартовой задержки и памяти находятся под ⚙. Оригинал по умолчанию выключен в режиме озвучки.
6. «Захватывать только видео» скрывает карточки и страницу в служебном источнике; это влияет на видеозахват. В исходном режиме картинка приходит прямо от YouTube во вкладке просмотра. ⚙ → «Качество YouTube» временно открывает штатные настройки качества; после выбора нажмите «Вернуть перевод», затем▶. Битрейт/FPS в popup относятся только к режиму захвата: это ограничения, а не гарантия реального FPS. Диагностика показывает фактическое разрешение и счётчики кадров.
7. Пауза останавливает просмотр; служебный источник продолжает обрабатывать звук впереди. Ползунок и «Перейти» внутри сохранённого готового диапазона используют прежние субтитры и WAV, без обращения к моделям и без смены эпохи. В режиме захвата возврат за окно декодера восстанавливает MSE из RAM и может занять время. В исходном режиме YouTube может заново загрузить картинку из сети. За пределами готового диапазона перематывается служебный источник, старые дорожки сбрасываются, начинается новый архив. Перемотка непосредственно в служебном YouTube всегда начинает новую эпоху.
8. «■ Завершить» прекращает захват, закрывает нашу вкладку/окно просмотра и возвращает к исходному YouTube. Закрытие плеера или источника также завершает сессию. Чужие вкладки не закрываются. Для нового видео начните новую сессию.

Звук служебной вкладки перехватывается tabCapture и не выводится напрямую на колонки. В режиме захвата в плеер приходит звук захваченного источника; в исходном режиме он воспроизводится родным плеером вкладки просмотра. Русская речь звучит отдельным HTMLAudioElement. Повторного захвата плеера нет: разрешён только URL YouTube `watch` и фиксированный ID служебной вкладки.

## Как устроена задержка

«Исходное YouTube»: `tabCapture(audio only) → AudioWorklet → модели`; картинка и оригинальная дорожка воспроизводятся вторым штатным YouTube-плеером без MediaRecorder, русская дорожка синхронизируется через мост content-script и общую шкалу времени. Источник продолжает играть впереди. Без интернета картинка в этом режиме доступна лишь в пределах собственного кэша YouTube.

«Захват вкладки»: `tabCapture → offscreen MediaRecorder (VP8/Opus) → BroadcastChannel → MediaSource плеера`.

Параллельно `AudioWorklet → PCM 16 кГц → WebSocket → Faster-Whisper → TranslateGemma → Qwen3-TTS → FFmpeg atempo → тот же плеер`.

Общий ноль — начало эпохи захвата. PCM-пакеты по5–10сек завершаются по паузе или лимиту. ASR использует beam5, перекрытие2.5сек и word timestamps; незавершённая фраза ждёт следующего пакета. Переводятся законченные реплики; соседние фразы одного участника могут объединяться до12сек. Субтитры и речь планируются по `video.currentTime`. Источник продолжает захват, пока плеер ждёт перевод.

Буфер 10–60 секунд задаёт **начальное накопление**, по умолчанию60. После старта уменьшение задержки ниже этой цифры само по себе не вызывает паузу: ждём только нехватку готового перевода/медиа. При ускорении накопленный запас расходуется, поэтому источник1× не позволяет смотреть бесконечно на2×. Фактическая задержка показана в диагностике. Клиент0.3.1 передаёт следующий пакет только после подтверждённого результата предыдущего; накопленный PCM остаётся в ограниченной RAM-очереди и не выбрасывается из-за пакетного прихода событий браузера. Лимит240сек PCM (до7.7МБ), при накоплении120сек источник явно останавливается по причине ёмкости, очередь дорабатывается. Сервер сохраняет защитный лимит6пакетов для неисправных клиентов. После seek старые ответы отклоняются и в сервисе, и в плеере. Диагностика transport разделяет ожидание модели, задержку доставки Worklet и разрывы его временной шкалы. Минимальный речевой пакет5сек (кроме завершения источника), максимум10сек.

Русская реплика подгоняется к интервалу исходной речи через FFmpeg atempo с сохранением высоты голоса. Ускоряется только слишком длинная реплика; более короткая не замедляется. Удаляется тишина по краям, слова не обрезаются. Видео не ставится на паузу ради завершения озвучки. Общая скорость просмотра всё ещё регулируется пользователем. Очень сильное ускорение может ухудшать разборчивость; качество перевода и совпадение границ ASR по-прежнему важны.

Под таймлайном всегда видны объёмы захваченного и переведённого буфера, очередь и RAM. Серая полоса — захваченное, зелёная — готовый перевод. Отдельные состояния показывают паузу источника, завершение захвата, отсутствие новых данных и ожидание ответа сервиса.

В полном экране наши controls и статус скрываются через2.5сек без движения при воспроизведении; субтитры остаются. Движение мыши/касание/клавиатура возвращают управление. Пауза, открытые настройки и клавиатурный фокус удерживают controls. В исходном режиме штатные панели YouTube скрыты под нашим управлением; кнопка «Качество YouTube» временно возвращает их.

## Длительная пауза и память

В режиме захвата архив хранит сжатые video/audio ArrayBuffer и WAV перевода в RAM: по умолчанию2048МиБ, настраивается от256до8192МиБ. В исходном режиме у нас хранятся только перевод/WAV, видео-кэш контролирует YouTube. Лимит относится к содержимому нашего архива, а не ко всей памяти Chrome/декодера/моделей. С флажком «Хранить просмотренное» сохраняется вся уже обработанная часть текущей эпохи. Без флажка просмотренное постепенно освобождается.

Фрагменты захвата имеют последовательные номера и SHA-256. При восстановлении архива проверяются порядок, наличие начала потока и контрольные суммы; WAV перевода также проверяются при возврате. Временные границы готового перевода и идентификатор эпохи отделяют доступный архив от ещё не обработанного участка. Это обнаруживает пропуск/изменение сохранённых байтов, но не доказывает отсутствие потерь на стороне сайта, тишины, неверного распознавания или всех выпавших кадров. Ошибки декодирования и пропуски кадров показываются отдельно.

Декодер MediaSource получает только короткое окно впереди (~30сек), поэтому большая пауза не заполняет весь браузерный SourceBuffer. Пауза120сек реально проверена в синтетическом Chrome-тесте с продолжающимся MediaRecorder: архив рос, позиция сохранялась, воспроизведение возобновилось без reset.

При приближении к лимиту исходный YouTube ставится на паузу **по причине заполнения памяти**, захват завершается и сохранённое можно досмотреть. Это не ожидание ещё не захваченного звука. Для продолжения после полного архива начните новую сессию или заранее увеличьте лимит. Всё ещё не захваченное будущее видео tabCapture не предоставляет. Автоматической записи на диск нет.

## Локальность и доступ

Сервис слушает `127.0.0.1:8765`; Ollama — `127.0.0.1:11439`. Расширение подключается только к первому. WebSocket проверяет точный `chrome-extension://<id>` Origin и случайный токен первым сообщением. Токен генерируется в `config.local.json` и `extension/local-config.js`; не публикуйте их. Identity расширения закреплена публичным `key` в manifest.

Записи исходного аудио/видео на диск нет. MediaRecorder отдаёт Blob только в память. Диагностика сервиса хранит ограниченные числовые метрики в памяти, без аудио и текстов реплик. Скрипт benchmark сохраняет **явно запрошенные** тестовые WAV в `reports/`.

```powershell
.venv\Scripts\python.exe scripts\read_metrics.py reports\session-metrics.json
powershell -ExecutionPolicy Bypass -File scripts\check.ps1
```

Проверки протокола используют явно обозначенную тестовую модель для гонок/безопасности. Это не доказательство работы CUDA или YouTube. Реальные замеры делает `scripts/benchmark.py`; `--qwen` требует дополнительно установленного `qwen-tts` и скачивает Qwen3-TTS в проектный HF_HOME.

## Ограничения

Поддержка только обычных страниц YouTube watch в Chrome, одна сессия, скорость **источника**1×. Пользователь подтвердил перевод в режиме захвата0.2; новый исходный режим0.3 требует отдельной проверки на настоящем YouTube. Автоматические тесты с локальным DOMfixture не заменяют её. DRM, live, Shorts, реклама и нестабильная сеть не заявлены поддержанными. Две YouTube-вкладки могут иметь разные рекламные вставки; при обнаружении рекламы просмотр приостанавливается с пояснением. Скрытие/минимизация источника может зависеть от Chrome. Фиксированная задержка и безошибочная точность перевода не обещаются.

Сначала проверен Faster-Whisper large-v3-turbo, после сравнения выбран полный large-v3: в реальном тесте10.8сек речи обработаны через WebSocket/ASR/перевод/TTS за3.58сек, восстановлены слова, искажённыеturbo. Это один небольшой пример, не универсальный тест качества.

«Различать говорящих» использует локальную нейронную сегментацию pyannote3.0 и NeMo TitaNet через sherpa-onnx на CPU. Сначала анализируется40сек диалога, затем скользящее окно60сек с шагом20сек; совпадающие участки и голосовые признаки связывают локальные метки с постоянными ID сессии. Первые реплики ждут этого анализа. Qwen получает чистые образцы без участков одновременной речи; референсы хранятся только в RAM и закрепляются за ID. Максимум8ID, включая возврат после seek. Короткие ответы могут требовать ожидания или собственного короткого образца. Это не идентификация личности/пола и не гарантия безошибочного разделения перебиваний/музыки. ⚙ позволяет вручную выбрать голос; уже сохранённые WAV при этом не меняются.

Native Messaging и ComfyUI не используются: сервис запускается одной командой. Яндекс Браузер и другие сайты — следующий этап.

WhisperLiveKit рассмотрен как альтернативный streaming-ASR; здесь оставлен прямой Faster-Whisper, чтобы явно контролировать эпохи и синхронизацию с захваченным видео. Выбор TTS по замерам отражается в отчёте; Qwen3-TTS не следует считать проверенным только по наличию benchmark-скрипта.
